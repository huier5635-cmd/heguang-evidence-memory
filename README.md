# Qianora 编程接口：仅统计日志的诊断版本

2026 年 10 月 31 日补充：[当前部署、方法、固定代码与容量限制](docs/Cycle2-部署与方法补充-20261031.md)。该说明的发布不等于官网已接收材料，也不启动 Full。

版本 `0.2.0.dev6+obs1`，基于已部署的 `0.2.0.dev6` 固定提交 `48ba53cbc2d7fb7a21b6ed3b10295b28319dfdda`。本分支增加请求统计，检索、索引、模型、数据格式和保留期均沿用 dev6。它不代表新的检索收益，不触发官方 Smoke 或 Full。

## 为什么需要

上一轮官方 Smoke 得分为零，但服务关闭了通用访问日志，现有记录不足以区分接口是否成功、是否返回空结果或是否只是修复失败。本版本只向服务日志输出固定格式的统计行，不读取官方问题作分析。

## 日志内容

每次 `/add` 或 `/search` 完成后记录操作类型、HTTP 状态、处理耗时、已消费请求字节数、交给响应通道的字节数、完成标志。经过校验的 Add 另记消息数量，成功 Search 另记返回条数和字符数。鉴权拒绝时可能尚未消费请求体，因此请求字节数为零不代表对方没发送内容。完成标志仅表示应用的发送调用成功返回，不证明客户端收到。

不记录 user/session/request 标识、查询、正文、路径参数、鉴权信息、来源标识、异常文本或堆栈。health 和其他路径不记录。没有后台采样、代理轮询、外部遥测地址或新增公网查询接口。日志输出失败不会改变原请求的响应或异常。

## 已验证范围

55 项服务检查通过，包括原版与诊断版的真实 HTTP 响应对照、鉴权/参数错误/冲突/超大请求、空结果、存储故障、断开连接和日志输出故障。合成数据使用真实固定 MiniLM，在同一个持久化数据库上重启切换，Search 返回 12 条记录、合计 41496 字符，HTTP 响应逐字节完全一致，数据库 SHA 不变，schema 签名相同。八个原存储/特征/选择/评分模块逐字节未改。这些是本地证据；不等于线上部署验证或正式得分。

## 复现

本测试的原版 HTTP 对照需要在本仓库的同级目录放置固定原版，目录名 `coding-memory-dev6`，其提交必须为上面的固定提交。安装依赖后运行 `python -m pytest tests/test_api.py tests/test_request_metadata.py -q`。原仓库的研究模型测试需要独立研究依赖，不能当作该诊断改动的服务检查。

## 发布边界

本分支用于代码审查与部署准备。部署必须先匹配所有十个原模块的 SHA，备份受影响文件，保留原密钥、数据库、模型、服务单元、Caddy 与文本赛道；检查失败回滚。是否已部署以独立部署回执为准。正式 Full 始终需要用户另行授权。
