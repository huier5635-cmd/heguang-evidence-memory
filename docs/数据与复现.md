# 数据与复现

## 固定公开来源

SWEContextBench 固定到数据集 revision `12c65bd15e2559bc808065565e941ee7bbbd008f`；VibeMemBench 固定到 `11164976b4f920cdb0d0cd570ca572e49acea1e8`。`data/pinned-inputs.json` 记录原始 30 个文件的字节数、摘要和固定 URL；`data/capacity-sample-receipts.json` 另存扩大后 120 条公开轨迹的下载回执。这些是输入清单，不含原始问题、补丁、密钥或私有轨迹。

下载脚本只访问公开数据站点，不需要账号，不执行数据里的命令。已有缓存也会校验 SHA256。Windows 请使用较短的数据目录，历史轨迹以文件摘要命名，避免长路径问题。

在项目根目录运行：

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-dev.lock
.venv/Scripts/python.exe tools/acquire_public.py --data C:/aml-public
```

当前开发机器使用项目外的研究目录；发布包不包含数据原文件。

## 读取边界

公开 Parquet 原文件包含目标解答字段。评测读取层对目标表只读取 `instance_id/repo/problem_statement/created_at`，不把目标 patch、test_patch、测试标签或答案给记忆系统。历史表允许使用其历史问题、讨论和实现补丁。作者关系标注只留在评测器中，系统不知道哪条历史被标为相关。

VibeMemBench 最初取 24 条更早历史轨迹，随后扩大到 120 条、9 种语言，用于接口兼容与存储验证，排除了全部目标轨迹。同仓库历史 PR 编号必须低于该仓库最早目标编号。这些样本不是官方 Coding 数据，也没有产生解题分数。

## 数据审计与划分

SWEContextBench 的 Related 表有 362 行、357 个唯一编号。两个编号对应互相矛盾的可见字段，予以排除。关系还要求同仓库、历史 PR 编号更小、历史 `created_at` 严格早于目标。最终只剩 78 道可用代理查询：开发集 63，仓库独立验证集 8，封存集 7。

过滤改变了原基准的任务集合。`created_at` 也不能证明历史补丁在目标开始前已经合并；这只是保守的时间代理。因此不与原论文分数直接比较。最早 40 题试跑使用了较弱的时间规则，已退出最终结论。

划分单元是仓库，种子固定为 `coding-20261023`。公开关系不完整，未标为相关的历史不一定真的无关；Hit@K 只表示作者相关历史是否进入前 K 个返回片段。

`results/dev8-data-separation.json` 另行核对了目标与历史的编号交集：历史表中有一个不符合本实验条件的目标编号，但全部 78 个合格目标均不在历史表中。当前开发检索及两个手动代码案例没有把自己的解答作为历史输入。这个审计不运行封存查询。公开 SymPy 案例的评测器在首轮补丁冻结后单独读取测试补丁，具体边界见 [真实编程案例](真实编程案例.md)。

## 复现当前检索实验

`--work` 必须指向不存在的新目录，脚本不会自动删除旧实验。以下两个实验可顺序运行，便于减少计时干扰：

```powershell
.venv/Scripts/python.exe tools/public_benchmark.py --data C:/aml-public --work C:/aml-runs/base-01 --output results/repro-baseline.json --profile baseline --noise 0 4 16 64
.venv/Scripts/python.exe tools/public_benchmark.py --data C:/aml-public --work C:/aml-runs/rarity-01 --output results/repro-rarity.json --profile rarity --noise 0 4 16 64
```

默认分块 3,600 字符、重叠 360 字符，总返回预算 32,000 字符。噪声参数是每条正例最多加入多少条更早、同仓库的负例，实际数量受历史池限制；不能当成官方四档噪声定义。

报告保留逐题实际干扰数、来源长度、返回长度、各指标、数据摘要和源码摘要。`historical_patch_retrieved` 仅检查作者关联历史补丁是否有至少 32 个字符进入返回文本，既不证明补丁完整，也不证明能修复当前任务。

`--split validation` 可以运行仓库独立验证集。`sealed_test` 要求冻结摘要清单；后来已冻结 0.2.0.dev2 并完成首次 7 题验证，见 [封存集首次验证](封存集首次验证.md)。现在这些查询已知，不能为了得到好看的结果反复使用并称为新盲测。复现旧冻结配置需恢复匹配的历史源码。

## 复现 HTTP 与容量实验

```powershell
.venv/Scripts/python.exe tools/trajectory_http_probe.py --data C:/aml-public --work C:/aml-runs/http-01 --output results/repro-http.json --message-batch 25
.venv/Scripts/python.exe tools/synthetic_scale_probe.py --work C:/aml-runs/scale-01 --output results/repro-scale.json --steps 50000
```

前者默认限制服务进程树 RSS 384 MiB、数据库及 WAL 512 MiB、180 秒；健康检查在关闭客户端之前停止，避免把测试器自身关闭连接误记为服务故障。初次 dev5 测试的一次健康错误未直接归因于服务；修正测试器生命周期后复测为零错误，原报告保留。

后者默认 50,000 组命令/输出，也就是 100,000 条消息，限制相同。RSS 是采样得到的进程树之和，可能重复计算共享页，也可能漏掉两次采样之间的峰值；不是操作系统硬内存配额。只回收实验自己启动且创建时间匹配的进程。

这些结果不替代官方约 1.8B Tokens 规模的验证。[官方范围](https://agentmemoryleaderboard.ai/competition/)

## 本地重排研究

`requirements-research.lock` 是可选研究依赖，基础服务不需要。合格方向是直接给“问题、候选片段”打分的 cross-encoder，而不是为学术候选换用其他 Embedding 模型。模型版本和文件摘要固定，下载权重不需要 API Key，推理不把数据发送到模型站点。

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-research.lock
.venv/Scripts/python.exe tools/acquire_reranker.py --model-dir C:/aml-models/minilm
.venv/Scripts/python.exe tools/reranker_ablation.py --data C:/aml-public --index C:/aml-runs/rarity-01 --baseline results/repro-rarity.json --model-dir C:/aml-models/minilm --cache C:/aml-runs/pairs.sqlite3 --output results/repro-reranker.json
```

这条命令复现早期固定候选消融，只重新排序基础检索已经返回的同一批原文，不能增加召回、改变总证据预算或补回未取出的补丁。配对最长 512 tokens；长问题保留首尾，长片段最多取三个分布窗口，属于待验证的近似。其 8 题验证结果见历史报告，不能代表新配置的独立质量验证。新候选池、权重与预算实验使用 `selection_ablation.py`，命令见 [上下文选择实验](上下文选择实验.md)。

## 历史版本与移植核验

`history/` 保存与已记录实验摘要匹配的源码快照，`history/report-sources.json` 写明每个报告对应哪些快照。需要精确重现历史结果时，先复制完整开发包到新的研究目录，再用相应服务源码快照覆盖代码；首次重排研究还需叠加对应研究工具快照。当前 API 版本的摘要与历史 dev5 报告不同，不能把历史数值伪称为新版本完整重测。

当前版本可用相同公开数据重新运行基础检索与重排消融。既有 `research/validation-plan.json` 属于 dev5 的预声明研究配置，不能直接当成新版本的冻结清单。`verify_reranker_port.py` 只检查移植一致性，不替代新的独立解题验证。

模型启用的真实 HTTP 复现命令：

```powershell
.venv/Scripts/python.exe tools/trajectory_http_probe.py --data C:/aml-public --work C:/aml-runs/http-rerank-01 --output results/repro-model-http.json --message-batch 25 --model-dir C:/aml-models/minilm
```
