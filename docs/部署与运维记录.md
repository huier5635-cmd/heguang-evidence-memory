### 独立主机清理任务

同日安装 `heguang-retention.timer`，每小时加不超过 120 秒随机延迟触发 `heguang-retention.service`，并开启 `Persistent=true`。清理任务以 admin 身份运行，即使 API 服务停机也独立执行；主机停机仍会暂停，开机后的补跑与应用启动前清理不能替代主机必须持续运行的运维要求。

任务执行 `/usr/local/libexec/heguang-retention.py`，仅对实际生产目录 `/home/admin/heguang/data/public-lexical` 调用固定源码中 `Store(...).purge_expired(29)`。这会按新增时间清理旧消息、写入记录、词项索引与检索块，并处理 WAL 与空闲页；不按消息中陈述的历史日期误删新写入。脚本和单元由 root 持有，不读取系统 API 密钥，不记录请求正文。

安装后的手动运行显示 `Result=success`、`ExecMainStatus=0`；timer、API、Caddy 均 active。该检查仅在当前合成数据上运行，没有用改变系统时间或等待 29 天的方式测试；删除逻辑的混合年龄测试另见已有保留期限测试。

sudo systemctl show heguang-retention.service --property=Result --property=ExecMainStatus

回退：保留原固定代码；若需停止公网，先停止 Caddy 和 `heguang-memory`。备份 Caddy 配置是 `/etc/caddy/Caddyfile.pre-heguang`。不要为排查问题打开未鉴权公网服务或输出环境文件中的密钥。

## 部署准备顺序

1. 固定代码和配置，记录提交、依赖与索引参数。保留公开源码副本；数据目录和密钥独立存储。
2. 为公网实例生成随机的本系统 API 密钥，保存于受保护的环境文件；该密钥不授予云账号管理员权限。
3. 使用单个 Uvicorn worker，由 systemd 维护进程。应用只监听回环地址；反向代理负责 HTTPS。
4. 验证反向代理配置、域名解析、证书、鉴权和防火墙，外部只能访问需要的路由。没有密钥的 Add/Search 应返回 401，health 可公开。
5. 在外部独立网络做合成预检，比较重复写入结果、隔离和返回字段。重启服务后再次确认持久化。
6. 模型模式先确认指定模型、权限、预算与调用失败处理，用极小合成样本验证后才扩大调用。
7. 完整材料就绪后申请赛事 Key，再进行官方 Smoke。资格、容量与固定版本确认后才发起 Full。

免费 DNS 可以为测试实例提供名称；它增加对第三方 DNS 的依赖，不等于拥有独立域名或得到可用性保证。例如 [sslip.io / nip.io 官方说明](https://nip.io/)支持将含 IP 的主机名解析至对应实例，并用 Caddy 申请 TLS。具体已部署的主机名、证书和外部验证结果应在成功后追加记录，不能把示例当成可用接口。

## 日常检查与恢复

运行服务后应记录实际 systemd 单元名。以下是以 `heguang-memory` 为例的运维命令，只有相应单元已经创建时才有效。

```sh
sudo systemctl status heguang-memory --no-pager
sudo systemctl status caddy --no-pager
df -h /
free -m
du -sh /home/admin/heguang/data
curl --fail http://127.0.0.1:8751/health
```

关注磁盘可用空间、WAL 增长、应用重启次数、模型错误与上游额度。健康接口返回 200 只能证明进程正在响应，不证明模型权限或正式全量容量。日志只保留不含正文的必要运行错误；不要临时打开请求体记录来排查正式评测。

服务异常时，先保存脱敏的错误状态，再检查依赖、环境文件是否存在、目录权限和磁盘。模型 503 要区分上游权限/额度/网络；不要换成未获赛事允许的模型，也不要悄悄退回 lexical 冒充同一模式成功。
