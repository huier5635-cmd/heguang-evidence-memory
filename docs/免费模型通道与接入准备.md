## 规范模型名称与通道标识

系统规范模型身份保持 `gpt-4o-mini`，向量模型保持 `text-embedding-v4`。直接调用时，请求使用 `gpt-4o-mini`；Vercel 使用带供应商前缀的路由标识 `openai/gpt-4o-mini`。这是该通道的请求格式，详见 [Vercel REST API](https://vercel.com/docs/ai-gateway/sdks-and-apis/openai-chat-completions/rest-api)。

现有标签提取继续使用 Chat Completions 和 `response_format={"type":"json_object"}`。OpenAI Docs 说明 JSON mode 支持该格式，同时仍需校验具体结构；本程序继续验证标签引用必须出现在原文中。参见 [OpenAI Structured Outputs / JSON mode](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)和 [gpt-4o-mini](https://developers.openai.com/api/docs/models/gpt-4o-mini)。本轮没有改变标签提示、分块或排序方法。

## 已准备的配置与保护

账户和密钥准备好后，Vercel 路由采用以下非秘密设置：

```text
AML_LLM_PROVIDER=vercel
AML_LLM_URL=https://ai-gateway.vercel.sh/v1
```

真实密钥仅放在受保护的运行环境 `AML_LLM_KEY`，不写进示例、仓库或聊天。已有直接兼容接口继续使用默认 `AML_LLM_PROVIDER=openai`。

代码为这条新路线做了具体检查：

1. Vercel 路由只接受官方 HTTPS 地址，不接受仿冒域名、查询参数或其他路径。
2. 请求模型固定为 `openai/gpt-4o-mini`；`providerOptions.gateway.only` 限定 OpenAI。没有配置其他模型的回退列表。供应商过滤的语义见 [Vercel 官方说明](https://vercel.com/docs/ai-gateway/models-and-providers/provider-options)。
3. 返回的模型标识须为规定的 gpt-4o-mini 标识或已知 2024-07-18 快照，否则返回错误，当前 Add 不提交。
4. HTTP 402（例如额度不足）立即报错，不重试、不显示上游原始错误正文。程序不调用充值接口。
5. research 索引签名记录 LLM 通道与地址；切换通道需要新数据目录。只取得 LLM key 仍不能启动缺少 embedding key 的 research 模式。

这不是对上游模型权重的独立鉴定，也不证明额度、地区、数据政策或正式比赛资格。真实调用前还要核对账户免费余额、充值状态及实际返回结果；正式私有评测仍需另行完成相应资格与数据处理核查。
