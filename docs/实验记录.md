# 实验记录 · 2026-10-23

## 当前状态

当前服务版本 `0.2.0.dev4`，展示名 Qianora（千绪），其存储与基础检索继承 `0.1.0.dev5`。当前对话独立开发。文本赛道冻结；Coding 已独立部署，独立申请仍是草稿，官方 Smoke/Full 未启动。保密凭据不进入项目。本地实验没有收费模型调用。下文保留各版本当时的结果；最新变化见文末。

## 检索基线与改进

当前 dev5 版本复测了同一组 63 道开发查询；默认 3,600 字符片段、32,000 字符总返回预算。

| 干扰上限/正例 | 配置 | Hit@1 | Hit@5 | Hit@20 | 历史补丁取回 | MRR |
|---|---|---:|---:|---:|---:|---:|
| 16 | baseline | 66.67% | 88.89% | 98.41% | 93.65% | 0.7663 |
| 16 | rarity | 69.84% | 93.65% | 100.00% | 93.65% | 0.8041 |
| 64 | baseline | 63.49% | 84.13% | 92.06% | 88.89% | 0.7320 |
| 64 | rarity | 65.08% | 87.30% | 95.24% | 87.30% | 0.7426 |

来源：`results/dev5-baseline.json`、`results/dev5-rarity.json`。较高噪声下 rarity 的历史补丁取回比 baseline 少 1/63，这个问题尚未解决。检索命中率改善不足以证明更高的代码任务解决率。

历史 dev2 仓库独立验证只有 8 道题：16 倍干扰时 Hit@5 从 7/8 到 8/8，补丁取回从 5/8 到 6/8。样本很少，不构成稳定优势的证据；本轮重排的独立验证结果另列于下文。封存的 7 道题未开启。

## 已试验但未采用的修改

不同历史任务的覆盖惩罚为 0.35 或 1 时，开发集 Hit@5 都是 93.65%，与不惩罚持平；补丁取回却从 93.65% 降到 85.71%。因此参数默认 0，不把这种重排纳入当前推荐配置。

1,800 字符片段在 16 倍干扰下的补丁取回提高到 96.83%，但 Hit@1/Hit@5 分别下降为 68.25%/92.06%。7,200 字符片段的 Hit@1 提高到 74.60%，其他主要指标持平；扩大到 64 倍干扰后，Hit@20 从 95.24% 降到 92.06%。没有发现一个片段长度在所有关注指标上稳定占优，继续保留 3,600 字符默认值。

这些是开发集参数消融，固定了总字符预算，但片段粒度不同，Hit@K 的含义也随之变化。不能把长片段的 Hit@1 提升单独当成模型能力跃升。

本地 BGE 向量试验在核对学术榜模型限制后终止，没有接入候选，也没有得到可采用的完整结果。后续仅研究不生成独立向量索引的 cross-encoder 重排。

## 工程验证

- 22 项单元/接口测试通过，覆盖原文、事务、隔离、跨 Add 配对、重启、冲突、保留期及损坏数据。
- 24 条公开历史轨迹共 3,007 条消息，经真实本机 HTTP 的 133 次 Add 后逐条恢复；验证 77 组跨 Add 配对。复测健康检查 89 次成功、0 次错误；服务进程树采样 RSS 约 61.1 MiB。原始报告是 `results/dev5-trajectory-http-repeat.json`。
- 100,000 条唯一合成消息写入同一用户数据库；抽样恢复 100 条、50 次唯一标识符查询均命中第一条。数据库 217,866,240 字节；采样 RSS 约 43.4 MiB；查询 P95 44.8 毫秒。`results/dev5-synthetic-scale.json` 保留原始数值和限制。

计时来自本地开发电脑，部分实验并行运行，不适合当成严格的配对性能结论。结构性查询、自然语言相关性、可执行修复率和云端全量容量是四种不同证据。

## 下一步的验收顺序

先确定能兼顾任务相关性与补丁证据的配置，完成开发集消融，再做独立仓库验证。之后需要实际编程 Agent 的可执行测试、单用户和多用户容量预算、云端稳定性及冻结版本核验。官方提交开关在这些验证完成前保持关闭。

任何“一等奖”或“已经最优”的判断目前都没有结果支持。

## 免费 cross-encoder 与接口移植

在固定的相同原文候选上，按开发集选择 RRF 权重 1，未调整独立验证集：

| 集合 | 原始 Hit@1 / Hit@5 | 重排 Hit@1 / Hit@5 | 原始 MRR / 重排 MRR |
|---|---|---|---|
| 开发 63 题，干扰 16 | 69.84% / 93.65% | 80.95% / 98.41% | 0.8041 / 0.8898 |
| 开发 63 题，干扰 64 | 65.08% / 87.30% | 74.60% / 93.65% | 0.7426 / 0.8070 |
| 仓库独立验证 8 题，干扰 16 | 75.00% / 100.00% | 100.00% / 100.00% | 0.8375 / 1.0000 |

这些数字来自 `dev5-cross-encoder-rerank.json`、`dev5-cross-encoder-noise64.json` 和 `validation-dev5-cross-encoder.json`。固定候选重排不会改变总体补丁取回率；63 题、16 倍干扰下有 7 道 Hit@1 改善、0 道退化，Hit@5 有 3 道改善、0 道退化。独立验证只有 8 题，且此前已检查过基础检索表现，不能称为完全未接触的最终盲测。封存集仍未开启。

首次模型消融约 184 秒；本地每题重排 P95 约 3.4 秒，最慢约 12.9 秒，不能只宣传基础全文检索的毫秒延迟。

移植后的 `0.2.0.dev1` 通过 8 个案例数值得分一致性核验，最大差为 0；API 不持久保存配对缓存。启用真实模型的本机 HTTP 测试恢复全部 3,007 条消息，健康检查 387 次成功、0 次失败，进程树 RSS 采样峰值 239,898,624 字节，约 228.8 MiB；见 `results/dev6-reranker-http.json`。这个测试主要检查协议和资源，不是相关性或全量并发测试。

## 0.2.0.dev2：选择顺序、较大样本与真实案例

改为先建立内部候选池、重排后才按最终预算选择完整记录；当前开发选择为融合权重 4、128k 字符。63 道开发查询在 64 档干扰下，至少一份完整相关历史补丁的取回从 84.13% 提高到 93.65%；Hit@5 仍为 93.65%。预算和返回文本量增加，不能把全部改善归因于模型，也尚未证明更高的代码解决率。逐项比较见 [上下文选择实验](上下文选择实验.md)。

新配置通过 8 个研究/接口一致性案例。启用模型的 120 条历史轨迹测试逐条恢复 13,093 条消息，跨 Add 配对 289 组；1,914 次健康检查成功、0 次错误；采样 RSS 峰值约 235.0 MiB。27 项单元/接口/免费调用约束测试通过。完整 Coding 规模及云端并发仍待验证。

Requests 公开案例的基线已能通过本地复现，因此不记为修复。SymPy 的首次独立冻结补丁未通过完整任务测试；随后查看公开失败并开发，通过三个目标测试函数。首轮失败和后续开发通过分别留档，没有无记忆对照，不能计算记忆的解题增益。详见 [真实编程案例](真实编程案例.md)。

双组公开草稿准备与零价格路由工具已经完成，未取得可用调用权限，生成请求为 0。7 道封存查询仍未开启，正式提交继续关闭。

## 冻结后的首次留出与 0.2.0.dev3 工程修复

0.2.0.dev2 封存后完成了首次仓库留出验证：7 道任务、4 个仓库；新旧各档 Hit@5 都是 7/7，完整相关历史补丁覆盖从 5/7 到 6/7，但 MRR 有退步。历史池只有 1–8 条，不能证明大噪声泛化。计划和结果见 [封存集首次验证](封存集首次验证.md)，这些查询不再是未用测试数据。

随后发现大请求内存问题：两份各约 64 MB 的 JSON 同时写入，原版峰值约 695 MiB；释放多余缓冲、分段摘要计算并限制大请求同时处理数量后降至约 377 MiB，原文均完整恢复。小请求仍保留两个处理名额。42 项测试通过。另修复默认 422 错误响应回显非法 Unicode 后自身编码失败的问题；三项曾失败的回归用例随后通过。

具体实现、原始数值与边界见 [大请求内存与并发](大请求内存与并发.md)。这些修改没有依据留出结果改排序参数；冻结查询也没有重跑为新的盲测成绩。本地开源代码模型方案正在准备，尚无同模型可执行解题对照分数。正式提交继续关闭。
