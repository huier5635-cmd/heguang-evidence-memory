# 本地模型对照 · 2026-10-23

两轮有、无记忆对照均未解决公开 SymPy 任务。当前不能声称记忆提升了解题率，也不能由检索 Hit5 推断一等奖水平。

## 运行的是什么

使用已开发过的 `sympy__sympy-27868`，原始基线为 `22fc107a94eaabc4f6eb31470b39db65abb7a394`。目标是 Mathematica 解析器的 Unicode 问题。手动开发结果与模型草稿分开保存；没有把本机已修好的源码送给模型。

模型是 Apache-2.0 的 Qwen2.5-Coder-7B-Instruct GGUF Q4_K_M，固定 revision `13fb94bfda8c8cf22497dc57b78f391a9acb426a`，文件 SHA256 `509287f78cb4d4cf6b3843734733b914b2c158e43e22a7f4bf5e963800894d3c`。llama.cpp b11669 的官方 Vulkan 运行包 SHA256 为 `2c07574e7bde71321cb785282b20cc821e951132149eeceeea32ddebdbf0598e`。

GPU 是 NVIDIA RTX 5070 Ti Laptop，显存约 12 GiB。最初 CPU 路径先触发内存保护，第二次运行后来失去进程且未恢复出草稿；停止原因不明，保留异常报告。发现 GPU 后，两轮分别约 36 秒完成，两份草稿都已保存，模型子进程均已回收。外部付费 API 调用为零。

服务仅监听 127.0.0.1，临时鉴权不进入日志或包。模型上下文 32768、输出上限 2048、temperature=0、seed=1729、无自动重试。模型输出只允许修改 Mathematica 生产文件的唯一原始片段；禁止目标测试文件、路径逃逸、模糊匹配或自动修复输出。

## 两组如何比较

两组共享原始源文件、问题和通用指令。有记忆组只多出固定检索得到的 8 条更早历史记录，共 21,381 字符。它们是服务排序结果的完整记录前缀，未截断记录正文。上下文预算比官方服务小，模型、运行器也与官方不同。

第一轮将历史放在当前源码之后；第二轮把历史放在当前源码之前，并对两组都在末尾重复原始问题。`research/prompt_layout.py` 和两个公平性测试验证两组公共内容相同、输入不被原地修改。第二轮属于已看到开发反馈后的提示词试验，不是新盲测，也不是官方 Answer 提示词的复刻。

两轮的模型输出都先保存并冻结，再经人工检查修改范围，最后才由评测工具加载公开目标测试。目标标准解答补丁未读取。该案例此前已手动开发过，所以即使一次通过也不能算独立盲测成绩。

## 实际结果

| 轮次 | 无记忆组 | 有记忆组 | 整题解决差值 |
|---|---|---|---|
| 第一轮 | 有效片段但只改类型标注，测试失败 | 引用已不存在的旧片段，修改无效 | 0 |
| 第二轮 | 引用错误变量名的旧片段，修改无效 | 修改有效，但两个修复目标测试仍失败 | 0 |

两轮基线都符合预声明条件：两个 FAIL_TO_PASS 测试失败，PASS_TO_PASS 测试通过。无效草稿直接计失败，不执行也不人工修好；只有全部目标修复测试与保留测试都通过才算解决。两轮来自同一道题，不能合并成两个独立样本。

原始响应、生成报告、代码冻结摘要、有效修改补丁和执行报告位于 `case-studies/sympy-27868/local-gpu-pair-01` 与 `local-gpu-pair-02`。包不附目标测试补丁或整份上游仓库，复现时从固定公开来源读取。

第二轮首次评测在下载原始归档时遇到 TLS EOF，没有得到测试分数。保留已冻结草稿，评测器只增加了可选的本地归档输入，仍严格核对相同 SHA256。随后使用正常证书验证的下载完成测试，没有重新生成模型输出。原评测器在历史快照中，修改说明见 `results/dev10-evaluator-acquisition-amendment.json`。

## 与参赛系统的关系

本地模型仅用于公开开发试验，不是 Add/Search 的组件，生产代码不导入该工具。参赛服务仍为全文检索、技术特征排序和可选 Reranker；不使用这个模型生成记忆或回答。申请、开源、部署及 Smoke 已获用户授权，Full 继续关闭。
