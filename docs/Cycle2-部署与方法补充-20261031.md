## 方法与来源

Add 按用户隔离保存原始编程历史，建立正文、路径、符号和稀有特征索引；SQLite FTS5 召回后，Search 使用固定 MiniLM 交叉编码器重排至多 16 对候选，再合并可核对的同源区间，返回保存的原始记录。Add 在持久化完成后同步响应，支持相同请求幂等、冲突拒绝和重启持久化。

Add/Search 不调用 LLM 或 Embedding API。重排模型为 Sentence Transformers 的 `cross-encoder/ms-marco-MiniLM-L6-v2`，固定 revision `233902d25c440f23af6f7d6e94d2946bac0bee0a`，直接使用上游提供的量化 ONNX 权重和分词器，不训练模型，也不生成答案。本项目独立实现的接口、存储和检索代码遵循根目录 MIT 许可证；模型、依赖、公开研究数据的原作者、使用方式与许可证见 [来源与许可](来源与许可.md)。研究用本地编程模型不属于线上 Add/Search。

原申请已经披露无 LLM／Embedding 配置。官方对开源方法 Add 模型的要求仍以 [参赛说明](https://agentmemoryleaderboard.ai/rules) 和 [API Guide](https://agentmemoryleaderboard.ai/api-guide) 为准；本文件不代替赛事方对该配置的明确解释或合规复核。

## 容量与运行限制

| 项目 | 当前配置 |
|---|---|
| 实例 | 2 vCPU、1 GiB 内存、30 GiB 磁盘 |
| 编程服务资源上限 | CPU 相当于 1 核；内存 384 MiB；交换 512 MiB |
| 模型和请求并行 | 模型单线程，内部同一时刻处理 1 个请求，外部并发排队 |
| 最大请求体 | 67,108,864 字节；超过返回 413，不静默裁剪 |
| 大请求 | 同一时刻处理 1 份 |
| Search | `top_k` 为 1..100；总证据预算 128,000 字符；最大同源区间 32,768 字符 |
| 代理响应头超时 | 30 分钟 |
| 数据保留 | 29 天，用户数据隔离 |

已有短历史并发、鉴权、幂等／冲突、隔离和重启持久化验证；obs1 的原模块摘要、重启持久化、真实固定模型下的 Search 响应一致和固定统计字段也有独立部署检查。统计不记录用户、会话、请求标识、问题、正文或密钥。

完整官方 Coding 语料规模和当前云端 Full 容量尚未验证，不能据此声明 Full 就绪。未部署候选的限定容器容量结果不作为当前服务的容量证明。本项目没有 Full 结果，不声明排名或已取得的修复收益。
