# 本地动手实验：从第一次运行到一次可解释的修改

对应 v0.1.1。下面的实验使用自己编写的合成消息和 `lexical` 模式，不需要模型账户，也不消耗赛事 Smoke/Full 次数。在 Windows PowerShell 的仓库目录执行；先确认 `python --version` 为 3.11 或更新版本。

## 1. 在同一个窗口启动并验证

虚拟环境让本项目的依赖与其它 Python 项目分开。`requirements.lock` 固定运行依赖，pytest 是另外安装的开发依赖。

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock
.venv/Scripts/python.exe -m pip install 'pytest>=8,<10'

$env:AML_MODE = 'lexical'
$env:AML_DATA_DIR = 'data/learning-01'
$env:AML_API_KEY = .venv/Scripts/python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
$memoryPython = (Resolve-Path '.venv/Scripts/python.exe').Path
$memoryServer = Start-Process -FilePath $memoryPython -ArgumentList @(
  '-m', 'uvicorn', 'aml_memory.api:create_app', '--factory',
  '--host', '127.0.0.1', '--port', '8750', '--workers', '1', '--no-access-log'
) -WorkingDirectory (Get-Location).Path -WindowStyle Hidden -PassThru
```

等几秒后，继续在这个窗口执行。子进程继承同一套环境变量，预检脚本也能读取同一个密钥，无需在两个终端间复制秘密。

```powershell
Invoke-RestMethod 'http://127.0.0.1:8750/health'
.venv/Scripts/python.exe tools/preflight.py --base-url http://127.0.0.1:8750
.venv/Scripts/python.exe -m pytest -q
```

预检应出现 `status: pass`、`official_evaluation: false`。它会写一条合成记忆，检查立即可检索、重试不重复、Top K 上限及另一用户查不到。若健康检查最初提示拒绝连接，稍后重试；若持续失败，按 README 前台启动服务查看启动错误。需要停止这个练习服务时，执行 `Stop-Process -Id $memoryServer.Id`。不要把它换成终止所有 Python 进程。

## 2. 自己写入和查询

保持上一步服务运行，使用新的学习用户。下面的密钥始终从当前环境读取。

```powershell
$memoryHeaders = @{ Authorization = "Bearer $env:AML_API_KEY" }
$memoryAdd = @{
  request_id = 'learn-write-01'
  user_id = 'learn-user-A'
  session_id = 'learn-session-01'
  messages = @(
    @{ role = 'user'; content = 'I keep a copper notebook for my astronomy class.' },
    @{ role = 'assistant'; content = 'Where do you study?' },
    @{ role = 'user'; content = 'I study at Lake Mere Observatory every Tuesday.' }
  )
} | ConvertTo-Json -Depth 8
Invoke-RestMethod 'http://127.0.0.1:8750/add' -Method Post -Headers $memoryHeaders -ContentType 'application/json' -Body $memoryAdd

$memorySearch = @{
  user_id = 'learn-user-A'
  query = 'Where do I study astronomy?'
  top_k = 5
} | ConvertTo-Json
Invoke-RestMethod 'http://127.0.0.1:8750/search' -Method Post -Headers $memoryHeaders -ContentType 'application/json' -Body $memorySearch | ConvertTo-Json -Depth 10
```

读结果的 `content` 和 `score`：返回的应是带来源的原始发言，包含 Observatory 那句，不能只是模型生成的结论。换成 `learn-user-B` 应返回空数组；再次提交完全相同的 Add 应成功；保留 `learn-write-01` 却改消息，应得到 409 冲突。409 表示同一写入标识不能代表两件不同的事情。

## 3. 直接观察六条消息的窗口

下面的命令不会启动外部模型，也不会写数据库；它只调用真实的 `Engine.documents()`。输入很短，所以只观察普通消息窗口。

```powershell
@'
from pathlib import Path
from aml_memory.config import Settings
from aml_memory.engine import Engine
from aml_memory.schema import AddRequest

request = AddRequest(request_id='window-demo', user_id='demo', session_id='s1',
    messages=[{'role':'user', 'content':f'Short message {i}'} for i in range(6)])
for stride in (2, 4):
    engine = Engine(Settings(data_dir=Path('data/unused-demo'), api_key='local-demo', window_stride=stride))
    print(stride, [(doc['start'], doc['end']) for doc in engine.documents(request)])
'@ | .venv/Scripts/python.exe -
```

预期结果为 `2 [(0, 4), (2, 6), (4, 6)]` 和 `4 [(0, 4), (4, 6)]`。这里的 end 不包含该位置，例如 `(0, 4)` 表示消息 0、1、2、3。来源头长度也计入长消息判断，因此换成长文本后不能继续套这个块数。

## 4. 第一次改参数

先停止本练习启动的服务，再把 `AML_WINDOW_STRIDE` 从 2 改为 4，使用新目录 `data/learning-02`，重新启动并写入同样的合成记忆。比较块数、结果顺序和正文长度；随后只改 `AML_BRIDGE_WEIGHT`，再做一次独立比较。

一张最小实验记录表就够用：

## 5. 常见错误该去哪儿找

| 表现 | 首先查看 |
|---|---|
| 启动时报缺少密钥 | 当前终端的 `AML_API_KEY`，不要打印密钥内容 |
| 401 | 客户端是否读取了与服务相同的密钥、请求头格式是否正确 |
| 409 | 是否重复使用同一 `request_id` 却改变了请求体 |
| 422 | 请求字段、`top_k`、多模态格式、返回媒体大小 |
| 503 | 索引配置与旧目录是否一致；模型模式下是否为权限、额度或上游故障 |
| 413 | 请求体是否超过本服务明确的 64 MiB 上限 |
| 查不到另一用户的数据 | 这是隔离的预期行为；检查实际 `user_id` |
