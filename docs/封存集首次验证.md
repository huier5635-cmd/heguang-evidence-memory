# 封存集首次验证：7 道任务、4 个仓库

`0.2.0.dev2` 开发包完成封存后，先写入 `research/selection-holdout-plan.json`，固定源码、数据摘要、模型、权重、预算和全部四档干扰设置，再运行此前未评测的仓库留出查询。该研究不提交官方评测，也没有打开当前目标的标准解答或测试补丁。

## 首次结果

| 请求的干扰上限/正例 | 旧 / 新 Hit@5 | 旧 / 新至少一份完整相关历史补丁 | 旧 / 新 MRR |
|---|---:|---:|---:|
| 0 | 7/7 → 7/7 | 5/7 → 6/7 | 1.0000 → 1.0000 |
| 4 | 7/7 → 7/7 | 5/7 → 6/7 | 0.8571 → 0.8214 |
| 16 | 7/7 → 7/7 | 5/7 → 6/7 | 0.8214 → 0.8143 |
| 64 | 7/7 → 7/7 | 5/7 → 6/7 | 0.8214 → 0.8143 |

旧配置是先装入 32k 字符再重排、融合权重 1；新配置先取内部候选池再选择、权重 4、最终 128k 字符。排序有退步，完整补丁覆盖改善，不能称为全面胜出。返回文本成本也不同。

报告为 `results/holdout-dev8-selection.json`。28 个运行条件来自同样的 7 道任务，只涉及 4 个仓库，不能当作 28 个独立任务。每道任务可用历史只有 1–8 条，16 和 64 档已饱和为相同历史池，因此这次结果不能证明真正大噪声场景下的泛化。

作者的相关历史标签只是检索代理；完整历史补丁不是当前目标解答。这个试验没有运行编程 Agent，没有测量记忆相对无记忆的修复增益，不能估算 CAMBench 分数或获奖概率。

## 使用后的纪律

这 7 道查询已经使用，之后只能作为已知研究数据。不能据此调参后把重跑称为新盲测。旧开发包保持原样，冻结源码另外保存为 `history/coding-dev8-source.zip`。

后续 `0.2.0.dev3` 改动属于请求内存、准入和错误处理；`Store.search/query_terms/ranking/feature_rarity/source_span` 以及重排、特征、归一化模块保持一致，源码核对记录在 `results/dev9-retrieval-source-continuity.json`。这解释了工程变更范围，但不会把旧版本的留出结果改称为新版本再次盲测。
