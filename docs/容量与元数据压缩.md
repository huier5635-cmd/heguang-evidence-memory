# 容量与元数据压缩 · dev4

dev4 接入路径、符号元数据的无损压缩。检索分词、排序、原文和重排配置不变。这是存储改进，不能作为新解题率或官方成绩。

## 实测与控制

只读核账覆盖 120 条公开轨迹、56 个仓库隔离库、13,093 条消息。docs 表约 10.7 MB，包含未压缩路径/符号 JSON。

| 条件 | 关闭连接后的数据库字节 |
|---|---:|
| 原公开轨迹库 | 70,553,600 |
| 只做数据库整理 | 69,099,520 |
| 原型压缩并整理 | 63,012,864 |
| 实际服务压缩并整理 | 63,135,744 |

原型比只整理组额外减少约 8.8%；实际编码增加格式头，额外减少约 8.6%。32,096 个特征字段解码后与旧值相同，432 次普通检索/内部候选池比较中，原文、顺序与分数逐项一致。

第一份控制报告在连接未显式关闭时计入日志，得到错误容量值。保留并标记失效；`*-closed.json` 是有效控制。原库检查前后摘要相同，从未修改。

## 编码与兼容

`feature_storage.py` 保持小 JSON 为文本；较大字段有收益时才保存为带 HCF1 标记、原长度的 zlib 数据。解码最多 1 MiB，核对长度、结束状态、尾部和字符串列表类型。损坏、解压膨胀及错误类型会失败，不继续用错误特征排序。

新签名为 schema 5 / feature_codec 1。旧库明确拒绝，需新数据目录重新写入；服务不会在线迁移。验证工具只转换公开数据库副本，不用于正式数据。

## HTTP 复测

带重排器、8 路客户端、2 个处理名额，120 条轨迹完成：13,093 条消息完整恢复，289 组跨 Add 配对、120 次重复和 120 次冲突检查通过。1,609 次健康检查无错误，子进程回收。数据库 64,610,304 字节，比 dev3 同类运行减少约 8.4%；并发写入和布局可能影响这个数值。采样进程树 RSS 254,242,816 字节，不把小幅内存差异称为确定收益。

47 项单元测试通过。新增测试覆盖完整恢复、损坏输入、解压边界、重启和旧签名拒绝。证据见 `dev11-feature-storage-production-parity.json`、`dev11-feature-http.json` 和 `dev11-unit-tests.json`。

## 全量容量仍未证明

官方约 1.8B tokens 与样本的规范化字符数、完整 JSON 字节数不是同一口径。`inspect_capacity.py` 明确列出不同假设，不能挑最小结果宣称 30GB 足够。线性推算不证明官方数据分布、WAL 峰值、词汇增长、重建空间或 Linux 吞吐。主机实际余量仍需登录后测量。

dev4 尚未部署或启动官方 Smoke。公开 dev3 固定提交保留，文本服务未改。用户允许申请与 Smoke，Full 继续关闭。
